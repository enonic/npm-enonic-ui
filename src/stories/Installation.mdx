# Installation

## 1. Install the package

With React:

```bash
pnpm add @enonic/ui react react-dom @radix-ui/react-slot
```

With Preact:

```bash
pnpm add @enonic/ui preact @radix-ui/react-slot
```

`@radix-ui/react-slot` is required either way — it backs the `asChild` prop. Two more peers are
optional, per feature: `focus-trap-react` for focus management in `Dialog` and other overlays, and
`react-virtuoso` for `VirtualizedTreeList`.

## 2. Load the styles

Components use Tailwind utility classes and render unstyled until a stylesheet is present. If your app
does not run Tailwind, import the prebuilt one and you are done:

```css
/* your app's entry CSS */
@import '@enonic/ui/style.css';
```

If your app runs **Tailwind CSS v4**, import the tokens through `preset.css` instead so components
share your utility build and your theme overrides apply. All four pieces are needed:

```css
/* Declare layer order first so your own overrides win over component styles */
@layer theme, base, components, utilities, overrides;

@import 'tailwindcss/theme.css' layer(theme);
@import 'tailwindcss/preflight.css' layer(base);
@import '@enonic/ui/preset.css'; /* design tokens, dark variant, base + custom utilities */
@import 'tw-animate-css'; /* component enter/exit animations */
@import 'tailwindcss/utilities.css' layer(utilities);

/* Relative to THIS file — adjust the ../ depth to reach node_modules */
@source '../node_modules/@enonic/ui';
```

`@source` is mandatory. Tailwind v4 generates only the utilities it finds in scanned sources, and it
skips `node_modules` by default. Without that line the component classes are never generated and
everything renders unstyled — this is the single most common setup mistake.

`tw-animate-css` is required on this path too. `Dialog`, `Toast`, and `Tooltip` emit `animate-in` /
`fade-*` / `zoom-*` classes that `preset.css` does not include. The prebuilt `style.css` already
inlines them.

### CSS exports

| Export                     | Contents                                                              | Use when                      |
| -------------------------- | --------------------------------------------------------------------- | ----------------------------- |
| `@enonic/ui/style.css`     | Fully compiled — Tailwind output + tokens + animations                | You don't run Tailwind        |
| `@enonic/ui/preset.css`    | Design tokens (`@theme`), dark variant, base styles, custom utilities | You run Tailwind v4           |
| `@enonic/ui/tokens.css`    | Design tokens + dark variant only                                     | Tokens without base/utilities |
| `@enonic/ui/base.css`      | Root font size + base text color                                      | Granular composition          |
| `@enonic/ui/utilities.css` | Custom `@utility` definitions (shimmer, `scrollbar-none`, …)          | Granular composition          |

## 3. Render a component

```tsx
import { Button, Input } from '@enonic/ui';

function App() {
  return (
    <>
      <Input label='Project' placeholder='Search projects' />
      <Button variant='filled' size='md'>
        Search
      </Button>
    </>
  );
}
```

## Preact projects

The published files import from `react` and `react-dom`, so a Preact app needs both aliased to
`preact/compat`. Using `@preact/preset-vite` covers this already. Configuring Vite by hand:

```ts
// vite.config.ts
export default defineConfig({
  resolve: {
    alias: {
      'react-dom/test-utils': 'preact/test-utils',
      'react-dom': 'preact/compat',
      react: 'preact/compat',
    },
  },
});
```

## Icons

Icons used inside components are bundled — no icon package is needed for components to render. Install
a Lucide package only to pass your own icon to a component that takes one, such as the `icon` prop on
`Tab`, `Link`, or `VirtualizedTreeList`:

```tsx
import { Tab } from '@enonic/ui';
import { Star } from 'lucide-react'; // lucide-preact in Preact projects

<Tab icon={Star} label='Favorites' />;
```
